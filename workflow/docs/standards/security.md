# 安全规范

## 目的与适用范围

本规范规定敏感信息处理、依赖与认证授权要求，以及安全审阅触发条件。

**主责角色：** 所有角色须遵守禁止项；Reviewer 与 QA 执行安全影响检查与结论记录。

## 1. 禁止写入敏感信息

禁止将敏感信息写入以下任何介质：

| 介质 | 示例 |
|---|---|
| 代码 | 硬编码密钥、内嵌凭据、生产 URL 含凭据 |
| 文档 | Spec、Plan、Review、QA 报告中的真实令牌或连接字符串 |
| 提交记录 | 提交 diff 中的密钥或 `.env` 内容 |
| 测试输出 | CI 日志、测试 fixture 中的真实凭据 |
| 工作项记录 | `workflow/docs/manager/<feature-id>.md` 中的敏感配置 |

须使用占位符、密钥管理服务或环境变量注入；本地开发使用 `.env`（已纳入 `.gitignore`）而非提交至仓库。

## 2. 安全审阅触发条件

当变更涉及以下任一领域时，Reviewer 必须进行安全影响检查：

- **认证** — 登录、会话、令牌签发与校验；
- **授权** — 权限模型、角色、访问控制；
- **输入处理** — 用户输入、序列化/反序列化、SQL 或命令注入面；
- **文件操作** — 上传、下载、路径遍历；
- **外部网络访问** — 出站请求、Webhook、第三方 API 集成；
- **依赖升级** — 新增或升级含已知漏洞风险的依赖；
- **敏感数据** — 个人身份信息、财务数据、健康数据等受保护数据。

检查范围须与变更实际影响面一致，并在 Review 报告中说明。

## 3. 发现疑似敏感信息时的处置

发现代码、文档、提交或日志中存在疑似敏感信息时，须立即：

1. **停止提交与合并** — 不得继续推送或合并含暴露内容的变更；
2. **移除暴露内容** — 从工作区、暂存区及已推送分支中清除（Git 仓库可用时，须评估是否需重写历史或轮换后 revert）；
3. **凭据轮换** — 按实际风险对已暴露的密钥、令牌或连接凭据执行轮换，并记录轮换状态。

处置过程须通知 Manager；必要时将工作项置为 `blocked` 直至风险消除。

## 4. 安全问题不得非阻塞放行

安全相关问题不得以非阻塞 Comment 结论放行合并或 QA Pass。

| 结论类型 | 是否允许放行 |
|---|---|
| Approve / Pass（安全问题已解决或不存在） | 允许 |
| Request Changes / Fail（存在未解决安全问题） | 禁止放行 |
| Comment（仅备注、未要求修改） | **禁止**用于安全问题结论 |

存在未解决的安全问题时，须取得 Request Changes 或 Fail 结论，修复并复审后方可继续。

## 5. 安全验证结论的记录位置

安全验证的范围与结论必须记录在以下之一：

- **Review 报告** — 对应切片目录的 `review.md`，当 Reviewer 执行安全影响检查时；
- **QA 报告** — 对应切片目录的 `qa-report.md`，当 QA 执行安全相关验收时。

记录须包含：检查范围、发现项（如有）、处置状态、是否允许继续合并。
