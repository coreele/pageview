# 文档工程规范

## 目的与适用范围

本规范规定文档分类、质量要求、审阅职责和生命周期管理。规范采用 Docs as Code：与相关代码同仓库、同分支、同审阅和同版本演进。

**主责角色：** Developer 维护开发文档；Reviewer 检查文档影响；QA 验收用户可见或运维可执行的文档。

## 1. 文档分类与主责

| 文档类型 | 主责角色 | 典型路径或产物 |
|---|---|---|
| 开发、API、配置文档 | Developer | 代码注释、README、接口说明、配置说明 |
| 架构决策 | Planner | 未拆分：`workflow/docs/features/<feature-id>/design.md`；已拆分：`workflow/docs/features/<feature-id>/<feature-id>-<sub-feature-id>/design.md`；以及 ADR |
| 部署与排障文档 | DevOps | `workflow/docs/deploy/`、运行与排障说明 |
| Spec（需求与行为合同） | Analyst | 未拆分：`workflow/docs/features/<feature-id>/spec.md`；已拆分：总览同路径 + 各子目录 `workflow/docs/features/<feature-id>/<feature-id>-<sub-feature-id>/spec.md` |
| 工作项与流程文档 | Manager | `workflow/docs/manager/`、工作项记录 |

各角色仅维护其主责范围内的文档；跨角色文档变更须在 Plan 的「文档影响」项中声明。

## 2. Plan 文档影响项

每个 Plan 必须包含「文档影响」项，分别说明以下三类文档的更新路径：

- **开发文档** — 代码注释、API、配置、开发者 README 等；
- **用户文档** — 面向最终用户的功能说明、操作指南等；
- **运维文档** — 部署、监控、排障、备份与恢复等。

若某类文档无需更新，须标记 `N/A` 并说明理由（例如：纯内部重构、无用户可见变更）。

## 3. 文档最低要素

文档必须包含以下要素：

| 要素 | 是否必须 | 说明 |
|---|---|---|
| 适用对象 | 必须 | 文档面向的角色或场景 |
| 前置条件 | 必须 | 阅读或执行前须满足的环境、权限或依赖 |
| 操作步骤 | 必须 | 可复现的操作或阅读顺序 |
| 预期结果 | 必须 | 完成后的可观察状态或结论 |
| 失败处理 | 适用时 | 常见失败情形及处理方式 |

上述要求适用于所有文档类型，不因参考性、架构性或流程性文档而豁免。

## 4. 链接、路径、命令与示例验证

文档中的以下内容须在 Review 或 QA 验收阶段验证其正确性：

- 内部与外部链接；
- 文件路径与目录引用；
- 命令行与脚本示例；
- 配置片段与代码示例。

验证方式包括：在目标环境中执行、对照当前代码库结构、或确认链接可访问。过时或错误的引用须在合并前修正。

## 5. Reviewer 与 QA 检查职责

**Reviewer** 必须检查：

- Plan 中的「文档影响」项是否完整，是否存在应更新但未声明的文档；
- 实现变更是否与已声明的文档影响一致。

**QA** 必须验收：

- 用户可见文档（功能说明、界面文案、帮助内容等）；
- 运维可执行的文档（部署步骤、排障流程等）。

验收依据为 Spec、Plan 及本规范第 3 节所列最低要素。未通过验收的文档须退回 Developer 或相应主责角色修正后复验。
