# UI / UX 工程规范

> 跨 feature 的通用质量底线，不是品牌手册。主题与视觉皮肤由 Spec / `ui-design.md` 决定。
>
> **由来（2026-07-26）**：引入 `design-ui` Skill 与工作项字段 `UI 表面: gui | cli | none`；复用 Design 门禁（不另增 UX 门禁）；light/dark **非**全局必选，由需求决定。

## 适用条件

| `UI 表面`（工作项记录） | 本标准 |
|---|---|
| `gui` | 适用「通用底线」+「GUI」 |
| `cli` | 适用「通用底线」+「CLI」 |
| `none` | 整份标准 N/A |

Design 门禁为 `required` 且 `UI 表面` 为 `gui` 或 `cli` 时，Planner 须产出切片目录下的 `ui-design.md`（见 `workflow/skills/design-ui`）。

## 通用底线（gui + cli）

- **信息架构**：一屏 / 一轮交互一个主任务；次要信息可发现但不抢主路径。
- **状态完整**：初始、加载、空、成功、错误、部分失败均有明确呈现。
- **错误可读**：原因 + 可执行下一步；禁止仅抛裸异常码作为唯一反馈。
- **反馈及时**：长操作有进行中指示；破坏性操作须确认（或 Spec 明确豁免）。
- **验收可映射**：UI/UX 决策须能回溯到 Spec 的 Given-When-Then；Spec 尚未写明时，在 `ui-design.md` 标「待 Spec 补充」并停止拍板需求。

## GUI 底线

- **层级与密度**：主内容优先；元信息分区明确，默认不淹没主视图。
- **焦点与键盘**：可聚焦控件有可见焦点；核心路径可用键盘完成（除非 Spec 声明仅指针）。
- **对比与可读**：正文与关键控件须可读；具体色值不在本标准锁定。
- **布局稳定**：加载 / 刷新避免无意义整页跳动；大片空白按 Spec（如空洞压缩）处理。
- **主题**：仅当 Spec 要求多主题或深色时，`ui-design.md` 定义 token / 切换策略；否则单主题即可。禁止将 light/dark 当作默认必做项。

## CLI 底线

- **帮助与用法**：`--help` / 用法错误须给出正确调用示例。
- **输出分层**：人类可读为默认；机器可读（若 Spec 要求）须稳定、可解析。
- **stderr**：承载诊断；成功路径不滥用 stderr。
- **非 TTY**：禁止依赖交互确认阻塞管道；颜色默认跟随 TTY / `NO_COLOR`。
- **退出码**：成功与常见失败可区分，并在 Spec 合同或 `ui-design.md` 中列出。
- **主题 / 深色**：非必须；仅 Spec 要求时定义。

## 与其他文档的边界

| 文档 | 职责 |
|---|---|
| Spec | 是否深色 / 多主题、展示哪些元信息、交互与错误合同、验收 |
| `design.md` | 模块边界、分层、技术选型 |
| `ui-design.md` | 本切片的布局、流程、状态与表面专属设计 |
| 本文件 `ui.md` | 跨切片复用的适用条件与质量底线 |

## 角色义务摘要

- **Manager**：登记时填写 `UI 表面`；Design=`required` 且表面 ≠ `none` 时，调度说明须含 `design-ui`。
- **Planner**：按门禁调用 `design-ui`；Plan 引用 `ui-design.md` 或标 `UI/UX: N/A`。
- **Developer**：有 `ui-design.md` 时按之实施，并遵守本文件对应章节。
- **Reviewer / QA**：存在 `ui-design.md` 时对照 Spec + 本文件 + `ui-design.md`；否则 UI 专项为 `N/A`。
